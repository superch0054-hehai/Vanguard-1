## 0. 背景与诚实声明

- 本次报告用的是**进行中测试**的每日增量数据（数据截至 2026-10-01 02:00），
  电池只跑了少量圈数（化成段），所以这是一份**阶段性报告**。
- 报告标题与图注已由程序写明"进行中/暂定值"，你在正文里也必须保持这个诚实度。
- 实验变量（两颗电池的差异是什么）**未提供**——涉及变量的判断一律降级为告警标记。

## 1. 系统提示词（每块写作时都遵守）

**完整原文在同目录 `_system_prompt.txt`（协会《提示词体系》L1 原文，不要改动）**。
它含角色、5 条铁律、《术语与口径对照》表（比容量 / 首效 / 保持率 / CE / EE / ΔV / 平台占比…的定义），
以及一条**防错关键**口径注：本体系是**负极半电池（Na‖HC）**，每圈先放电后充电，
效率口径 = **充电 ÷ 放电**，故首效 <100%（89.95% 量级）；**所有效率数值由程序给出，
你只引用、绝不自行换算**。

写每一块之前先读它。三条最容易忘的：

1. **只引用不重算**：数值原样引用数据包字段，不做加减乘除、不四舍五入改写、不自行拟合；
2. **无据不写**：字段缺失就写"（该项数据未提供）"；整块数据不足以成段就写
   【该块数据不足：<缺失字段>，暂不生成】；
3. **数据包里的 `instructions` 是给程序/你的约束，不是正文素材 —— 一个字都不能写进报告**；
   同理 `notes` 里带 ★ 的行是对你的提醒，引用前先判断它是不是"可以写进正文的口径说明"。

## 3. 自检校验规则（每块输出后逐条过）

| # | 规则 | 不合格就重写 |
|---|---|---|
| 1 | **数值溯源** | 输出中每个数字必须能在**本块数据**中找到原值 |
| 2 | **数值编造** | 数字不在本块数据中 → 判为编造 |
| 3 | **禁用词** | 显著提升 / 显著改善 / 证明了 / 表明该变量有效 / 大幅 / 最优 / 完美 |
| 4 | **标签污染** | 出现 `<` `>` `#` `\|` 或三反引号 |
| 5 | **小标题格式** | S41*/S42* 首行必须 ≤20 字且不含编号与句号 |
| 6 | **图表号一致** | 引用的"图 N / 表 N"与提示词一致 |
| 7 | **n=1 兜底** | S41A~D、S51A、S51C、S35C 必须含"波动范围 / 复测 / 需验证 / 可能"之一 |
| 8 | **长度** | 超出提示词要求区间 ±50% | 告警，不重写 |

## 4. 出报告：跑这一条命令

> ★ **流程只写在这一节**（其他文件（入口页/README）只是摘要，冲突时以本文件为准）。
> 判断类章节（**3.6 横向对比、4.1 核心结论、4.2 机制、4.3 建议、5.2 展望**）
> **由 AI 写**，其余段落（数据句）由程序填；你写的段里**不许出现测试数值**。

```bash
bash 出报告.sh          # 在任务包目录里跑；内部依次做下面五步
```

它内部做的五步（你不用手敲）：

1. `compose_paragraphs.py --mode refresh` —— 程序段按最新 live 数据重填
   （**AI 写过的段落由「出处台账」保护，不会被动**）；
2. `write_ai_sections.py` —— 调本机模型**一次写完** 21 段判断正文 → `批量稿.json`
   （要求见 `批量写作-3.6_4.2_4.3_5.2.md`，其中第五条：不许写测试数值）；
3. `split_batch.py` —— 拆成段落文件并当场过闸；不合格的会自动带原因回灌重写一次；
4. `validate_paragraphs.py` —— 全文过闸，要到「硬性不过 0」；
5. `render.py` —— 组装报告，**文件名带本次选择**：`SOH分析报告_<通道A>_vs_<通道B>.html`（正式数据集那份带 `-正式数据集` 后缀）。

全流程约 3~5 分钟（大头是第 2 步那次模型调用）。跑完把报告路径与校验结果回报。
