# 使用指南（部署与日常使用）

> 全部命令**复制粘贴**即可；下文【盒子】= TY1200（Debian 12），【采集 PC】= 跑东华软件的 Windows 机器。

## 一、盒子侧（一次性部署）

```bash
# 1) 把 dh_tools/ 拷上盒子（从笔记本/PC 都行）
scp -r dh_tools admin@<盒子IP>:~/dh-lab/tools

# 2) 一键部署：自检(25 项) → 试跑 → 构建镜像 → 启动容器 → 打印盒子 IP
ssh admin@<盒子IP> "bash ~/dh-lab/tools/install_on_box.sh"
```

说明：
- 容器名 `dh-collect`，`--restart unless-stopped`（盒子重启后自恢复）；
  挂载 `~/dh-lab/inbox:ro`（收件箱，只读）+ `~/dh-lab/outbox`（输出）。
- 盒子不通外网时，脚本会用 `Dockerfile.localbase`（以盒子**已有镜像**为底）离线构建。
- **还原**：`docker rm -f dh-collect && rm -rf ~/dh-lab`。
- **只动 `~/dh-lab`**；不要停止/重建盒子上其它容器。

## 二、采集 PC 侧（一次性配置）

```powershell
# 1) 取四个脚本到 D:\（或任意目录，脚本与工作区放在一起即可）
scp admin@<盒子IP>:/home/admin/dh-lab/tools/dh_grab.ps1      D:\
scp admin@<盒子IP>:/home/admin/dh-lab/tools/dh_grab.bat      D:\
scp admin@<盒子IP>:/home/admin/dh-lab/tools/dh_push.ps1      D:\
scp admin@<盒子IP>:/home/admin/dh-lab/tools/push_to_box.bat  D:\

# 2) 告诉抓取器"软件数据目录"在哪：与脚本同目录建 paths.txt，内容只有一行
Set-Content -Path 'D:\paths.txt' -Value 'D:\你的软件数据目录' -Encoding UTF8

# 3) 生成 SSH 密钥并把公钥交给盒子（一次；老版 OpenSSH 不许 ed25519，用 RSA）
ssh-keygen -t rsa -b 4096
type $env:USERPROFILE\.ssh\id_rsa.pub | ssh admin@<盒子IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# 4) 建两个计划任务（管理员 cmd；每分钟各跑一次）
schtasks /create /tn dh-grab /tr "D:\dh_grab.bat" /sc minute /mo 1 /f
schtasks /create /tn dh-push /tr "D:\push_to_box.bat" /sc minute /mo 1 /f
```

### 行为说明

| 源目录发生 | 结果 |
|---|---|
| 新增文件/文件夹 | 抓取 → 推送 → 解析（≤2~3 分钟到 Agent） |
| 文件被修改（同名同路径） | 重新抓取推送；盒子**覆盖**并**只留最新记录** |
| 文件被删除/改名 | 记入"待删清单" → 推送器让盒子把对应文件移入 `~/dh-lab/_trash/<时间戳>/`（**回收，不硬删**） |

安全阀：源目录不可达 → 本趟跳过；"消失"数量超过总数 20% → 只告警、不动清单（防误删）。

### 闪窗隐藏（可选）

计划任务默认会闪一下黑窗（无害）。用 VBS 隐藏启动器可彻底消除，见 `现场操作单.md` 里的"办法 A"。

## 三、验收与日常自查

```bash
# 盒子上的产物
ssh admin@<盒子IP> "head -3 ~/dh-lab/outbox/摘要.md | tail -1"     # 收录/待支持统计

```

## 四、常见问题

| 现象 | 处理 |
|---|---|
| 盒子没收到新数据 | 采集 PC 上跑一次 `dh_grab.bat` / `push_to_box.bat`，看 `DH_export\_state\dh_grab.log`、`dh_push.log` |
| 日志写"源目录不存在" | `paths.txt` 那一行写错（必须写"罩得住实验文件夹的那一层"，且是脚本同目录） |
| 日志写"推送失败…退出码" | 网络/盒子不可达；**保持原样，恢复后下一趟自动补推**（数据不丢） |
| 改了文件但盒子没更新 | 确认装的是新版抓取器（账本含大小+修改时间；文件里可见 `pending_delete` 字样） |
| 想强制全量重同步 | 删 `_state\grabbed.txt`（下次全量重抓重推，盒子按指纹去重不会重复记录） |
| 盒子容器重启用多久 | 1 秒级；收件箱/输出目录是主机挂载，数据不丢；不影响其它容器 |

## 五、pull 模式（盒子主动拉取 · 当前生产模式）

> 现在同步由**盒子**发起，采集 PC 上**不需要任何我们的程序**。

**前提（采集 PC 上一次性）**：Windows 自带 OpenSSH 服务 + 一个只读账号 + 公钥装在
`C:\Users\<账号>\.ssh\authorized_keys`（注意：本机账号家目录可能带机器名后缀，如 `dhbox.Allnex-Hohai`）。

**盒子（admin，无需 sudo）**：
```bash
# 手动试跑
python3 ~/dh-lab/tools/dh_pull.py --pc dhbox@<PC_IP> --src 'D:\数据目录' --once
# 常驻（cron 每分钟）
( crontab -l 2>/dev/null | grep -v dh_pull.py ; \
  echo '* * * * * cd /home/admin/dh-lab/tools && /usr/bin/python3 dh_pull.py --pc dhbox@<PC_IP> --src "D:\数据目录" --once >> /home/admin/dh-lab/_state/dh_pull.log 2>&1' ) | crontab -
crontab -l
```

**要点**：对 PC 只读；增=拉取、改=覆盖、删=移入 `~/dh-lab/_trash/`；
**必须用 `scp -O`**（老版 Windows OpenSSH 的 SFTP 会把大文件截断在 204800 字节）；
拉取后自动核对大小（不符→删除重拉）。

**回退到 push**：`schtasks /change /tn dh-grab /enable` + `/tn dh-push /enable`。
