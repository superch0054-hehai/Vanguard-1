# 报告链路 · 提示词体系修复（P0–P4，2026-10-02 晚）

起因：把协会《…第二版》报告和项目组《提示词体系 v1.0》原始文档逐条对照后，发现我们
落地的是"精简子集"，丢了最要命的**术语口径表**与**校验闭环**。本轮把丢掉的补回来。

## P0 效率方向口径（改数字的一条）

- **正确口径**（体系文档 L1《术语与口径对照》＋"防错关键"注）：本体系是**负极半电池
  （Na‖HC）**，每圈**先放电**后充电，效率 = **充电 ÷ 放电**，首效 <100%（89.95% 量级）；
  不可逆容量 = **|放电 − 充电|**（取绝对值）。
- 我们原来全项目算的是 放电 ÷ 充电（正极/全电池口径）→ 首效 111.79%、不可逆容量为负、
  还误把正常圈标成"CE 异常段"。
- 实现：**口径只此一处** —— `probe.ce_pct(chg, dis)` ＋ 开关 `CE_CHARGE_OVER_DISCHARGE`
  （换体系改这一个开关）；`figures` / `report_pack` / `probe` 全部调用它。
- 副作用修正：任一侧容量为 0 → 返回 `None`（进行中数据末圈只有放电工步，
  原来会算出 0% 并把稳态均值从 99% 拖到 65%，实测踩到）。
- `ce_never_healthy`（控制台失效电芯告警）改用**放电/充电比**判定 ——
  新口径下"没在放电"会让 CE 趋于无穷或 None，判不出来。

**与参考报告交叉验证（真机数据）**

| 指标 | 我们（改后） | 协会第二版 |
|---|---|---|
| 首效 | 89.45 / 89.75% | 89.95 / 90.83% |
| 首圈不可逆容量 | 33.86 / 32.13 mAh·g⁻¹ | 31.75 / 29.90 mAh·g⁻¹ |
| 稳态库仑效率 | 98.07 / 98.75% | 99.937 / 99.961% |

## P1 契约补件：把"写死的东西"变成"数据给的"

- **图号/表号**：12 处"末句写……见图 N/见表 N"全部改成读 `figure_ref` / `table_ref`；
  编号唯一出处是 `report_pack.BLOCK_REFS`。**以后改图序/章节顺序零重跑正文。**
- **方向词由程序给**：`avg_v_trend`（上升/下降/基本持平）、`dV_trend`、`peak_gap_trend`
  ＋逐圈峰间距 `peak_gaps_mv`；提示词里"由首圈 X 增大至第 Y 圈"这类**写死方向**的句子删掉，
  改成"方向取数据包字段"。
- **差值由程序算**：`ce_diff_pp`、`discharge_sp_diff`、`irreversible_diff_sp`、
  已补齐的 ΔV/EE/平台占比差值（模型不再自己相减）。
- **数值就地取好位数**：契约里直接给两位小数/三位小数（铁律说"不得四舍五入改写"，
  那就别给 14 位浮点逼模型取整）。
- **`notes` / `instructions` 分离**：`report_pack.split_notes()` 机械拆分
  （含"不得/禁止/不要/必须…"的进 `instructions`，其余是可引用口径）。
  起因：S31C 把 notes 里给模型的约束句原样抄进了正文。

## P2 程序侧校验闭环（`validate_paragraphs.py`，新）

`python3 validate_paragraphs.py --package 报告任务` → 退出码 1 表示有硬性不过；
明细写 `failed_blocks.json`，每条附 **5-B 回灌修复提示**。检查项：

1. 数值溯源（**数值比较**，认单位换算变体：数据 0.2231 V ↔ 正文 223.1 mV）
2. 未提供字段的引用（并入 1）
3. 禁用词 4. n=1 结论句 5. 机制措辞 6. 格式污染/元话语
7. 长度（只告警）8. 图号表号引用必须与数据包一致
9. **5-B 方向一致性**：数据说"减小"、正文写"增大" → 判失败
10. **instructions 泄漏**：正文出现数据包里给模型的约束句（长片段匹配，防改写前缀）→ 判失败

首次在真数据上跑：把 S31C（抄指令）与 S34A（方向与数据相反）**都抓出来了** ——
这两条正是模型自检从没报过的错。
