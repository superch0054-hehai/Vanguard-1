# 独立性与合并说明（给主干开发者）

## 本分支的定位

- 分支只**新增**内容：`dh_tools/`（工具与脚本）、`docs/`（文档）、顶层 `README.md`。
- **未修改主干任何既有文件**（无改动、无删除）→ 对本分支做任何操作都不会影响主干现状。
- 因此本分支可以长期独立存在；主干开发者可以随时审阅、择机合并，或完全不合并。

## "合并（merge）"是什么意思

合并 = 把本分支的提交**并入主干历史**。具体到文件层面：

| 合并后 | 会发生什么 |
|---|---|
| 新增文件（`dh_tools/`、`docs/`） | 它们的**目录会出现在主干里**（就像主干里多了一个文件夹） |
| 主干既有文件 | **不会被改动**（本分支没碰过它们） |
| 运行层面 | 两边**仍然完全独立**：东华这套脚本/容器与主干的新威流程不共享代码、不共享数据目录、不共享进程 |

也就是说：**"合并"只是把文件放进同一个仓库里，不会把两个系统耦合起来**。合并后仍然可以：单独部署东华侧、单独升级、单独删除（删掉 `dh_tools/` + `docs/` 即可完全移除，不留痕迹）。

## 如果希望"合并后仍绝对独立"

三种做法（任选，主干侧决定）：

1. **目录级隔离（本分支现状）**：东华全部内容收在一个顶层目录 `dh_tools/` + `docs/`，主干代码零接触。最省事，也是默认。
2. **`git subtree`**：把本分支作为 subtree 并入（例如放在 `integrations/donghua/`）；主干可随时 `subtree pull` 更新，也可整体移除。
3. **子模块 / 独立仓库引用**：主干只放一个 README 指针，东华侧作为独立仓库维护。

## 数据与运行时的隔离（已实现）

- 东华管道只使用 `~/dh-lab/`（收件箱/输出/工具）；不写其它目录。
- 只操作自己的容器（`dh-collect`）；不触碰其它容器（如 vLLM / Agent）。
- 采集 PC 侧对源目录**只读**；唯一新增写入是"软件自己导出/写入的新文件"。

## 建议的审阅顺序（给主干开发者）

1. 本 `README.md` → 了解数据流与目录结构；
2. `docs/更新说明.md` → 技术要点（文件格式结论、复现要点）与已知限制；
3. `docs/使用指南.md` → 部署与日常使用；
4. `dh_tools/parse_dat.py` 与 `dh_tools/dh_collect.py` → 核心实现（均有注释与自检）；
5. `dh_tools/selftest_dh.py` → 运行 `python3 selftest_dh.py`（25 项自检，零依赖）。
